# 收集玩家的遊戲紀錄

玩家在你的遊戲裡做了什麼——進了哪一關、花了多久、解了幾則提示、打錯了什麼答案
——可以自動流進**你自己的 Google 試算表**。

資料不會經過謎生的伺服器。**它是你的玩家的資料，所以它應該在你手上。**

不做這一步遊戲照樣能玩，只是收不到紀錄。

## 先看你會拿到什麼

試算表上會有兩張分頁。

**「遊戲紀錄」**——每一件事一列，原始資料：

| 事件 id | 遊戲 | 這局玩家 | 時間 | 事件 | 關卡 | 內容 |
|---|---|---|---|---|---|---|
| a1b2… | 福德之路 | c26… | 2026-09-20 10:37:57 | mission_start | 3 | |
| c3d4… | 福德之路 | c26… | 2026-09-20 10:39:01 | answer_wrong | 3 | 土地公 |

**「報表」**——按一下選單就重算，看得懂的版本：

```
整場
開始遊玩            48 組
完賽               31 組    65%
全程花費（中位數）    72 分

每一關
關卡   進來  通過  通過率  花費中位數（分）  解提示  答錯  放棄
1     48    47   98%    6.5             3      5    0
2     47    44   94%    11              12     28   1
3     44    19   43%    24              41     96   8     ← 卡在這裡
...

最常見的錯誤答案
關卡   玩家打了什麼    次數
3     土地公         31
3     福德正神        12
```

**最後那一塊通常最有用**：它是「你以為的答案」跟「玩家以為的答案」之間的差距，
也是你改題目時唯一的依據。

## 設定（大約十分鐘，只做一次）

### 1. 開一張新的 Google 試算表

用一張全新的，不要用你放遊戲資料的那一張——紀錄會一直長，混在一起很難看。

### 2. 貼上程式碼

在那張試算表上：**擴充功能 → Apps Script**。

把編輯器裡原本的東西**全選刪掉**，再把下面這一整份貼進去
（右上角有複製鈕）。

> 不要只貼一部分，也不要試著跟原本的內容合併。整份蓋掉就對了。

<<< @/publish/collect.gs{js}

按左上角的磁片圖示存檔。

### 3. 部署成「網頁應用程式」

右上角 **`部署` → `新增部署作業`**。

- 左邊的齒輪 → 選 **`網頁應用程式`**
- 「執行身分」：**我**
- 「具有存取權的使用者」：**任何人** ← **這一格選錯就完全收不到資料，而且不會有任何錯誤訊息**

按 `部署`。

中間會要你授權，並且出現一個畫面說「**Google 尚未驗證這個應用程式**」。
那是因為這段程式碼是你自己貼的、沒有經過 Google 審查——按 `進階` → `前往（不安全）` 就好。

### 4. 複製網址，貼進 config 表

部署完會給你一條 **「網頁應用程式」網址**，結尾是 `/exec`，長這樣：

```
https://script.google.com/macros/s/AKfycb.../exec
```

複製它，貼進你**遊戲試算表**的 `config` 表、`recordUrl` 那一欄。

> `config` 表沒有 `recordUrl` 欄位的話，在最後面自己加一欄，欄名就叫 `recordUrl`。

### 5. 測試

回到 `/create`，載入你的遊戲，按 **「測試連線」**。

然後**打開你的試算表看一眼**——「遊戲紀錄」分頁應該多了一列測試資料。

**一定要真的去看。** 網頁沒有辦法知道資料有沒有寫進去（Google 不會回話），
所以「按了沒有跳錯誤」不代表成功。

## 之後怎麼看報表

打開試算表 → 上方選單 **`謎生` → `重算報表`**。

看不到「謎生」這個選單的話，把試算表重新整理一次（那個選單要在開啟時才會長出來）。

報表**不會自己更新**，每次要看都按一次。所以報表第一行寫著「資料截至 ⟨時間⟩」
——先看那一行，確認你看的不是三天前的數字。

## 常見狀況

### 收不到資料

按順序檢查：

1. **`config` 的 `recordUrl` 填了嗎、是不是 `/exec` 結尾**
2. **部署時「具有存取權的使用者」是不是「任何人」**——這是最常見的一個
3. **玩家有沒有真的玩到**——遊戲紀錄要有人玩才會有

### 改了程式碼卻沒有效果

**「存檔」不等於「部署」。** 存檔只是存起來，網址上跑的還是上一個部署的版本。

要重新部署：**`部署` → `管理部署作業` → 右上角鉛筆 → 「版本」選 `新版本` → `部署`**

> ⚠️ **不要按「新增部署作業」**——那會給你一條**新的網址**，舊的那條就失效了，
> 而你填在 `config` 裡的是舊的。

分得出來有沒有成功的方法：「遊戲紀錄」表頭最後一欄寫著 `內容 (v3)`。
版本號會跟著程式碼一起更新，看到新的就代表新版真的在跑。

### 資料會不會掉

玩家的事件先存在他自己的手機裡，再定期送出去，而且**送成功才會標記為已送**。
所以中途沒訊號、走進地下室、把分頁關掉都不會掉——下次打開遊戲會把積欠的補送。

不過如果玩家玩完就再也不打開那個網頁，最後那一段可能會留在他手機上。
真正保險的作法是**在終點提醒玩家「打開遊戲確認一下」**。

## 要知道的兩件事

**這條網址是公開的。** 它寫在 `config.csv` 裡，而那個檔案玩家打得開。
也就是說，任何拿到它的人都可以往你的試算表寫東西。

一場活動、幾十個人的情境下這不是問題（要故意去翻檔案才找得到）。
但如果你的遊戲是公開販售、會被很多人研究的，這件事要重新想。

**「組」不是「人」。** 報表上的「組」指的是一次遊玩：
同一支手機重新開始會算成兩組，一群人共用一支手機算一組。
拿這些數字去寫報告的時候要講清楚，不要說成「幾個人」。
