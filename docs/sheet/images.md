# 圖片怎麼填

所有 `img`、`avatar`、`backgroundImg`、`straight` 之類的欄位，都是填**圖片的位置**。

## 方法一：貼網址

Google 雲端硬碟的分享連結可以直接貼——謎生會自己轉換成看得到的格式。

::: warning 權限要開
共用權限設成「**知道連結的人都可以檢視**」，否則只有你看得到，玩家看到的是破圖。
:::

其他圖床的直接連結也可以。

## 方法二：用本機資料夾

把圖片放在一個資料夾裡，在 `/create` 選「改用本機資料夾」。
這時候欄位改填**檔名**就好（例如 `土地公.jpg`）。

適合圖片還在調整、不想每改一次就重新上傳的階段。

## 該做多大、什麼比例

遊戲畫面是一支直立的手機（大約 415×900），所以**多數圖都是直式的**。

| 用在哪 | 比例 | 建議尺寸 | 怎麼被顯示 |
|---|---|---|---|
| `backgroundImg`（封面、關卡、單頁背景） | **直式 2:3 或 9:16** | 1080×1920 | 填滿整個畫面，**超出的部分會被裁掉** |
| `straight`（角色立繪） | **直式 2:3 或 9:16** | 1024×1536 | 完整放進畫面、**上緣對齊**，不會被裁 |
| `avatar`（角色頭像） | **正方形 1:1** | 600×600 | 裁成圓形，只顯示大約 40 點 |
| `prop` / `story` 的圖 | 任何比例 | 長邊 1500 以上 | 完整顯示，玩家可以點開放大、雙指縮放 |
| `Wheel` 的四層圖 | **正方形 1:1** | 1000×1000 | 疊在一起轉，**四層要對齊同一個圓心** |

::: warning 背景圖會被裁
背景是「填滿」不是「放進去」——手機比例跟你的圖不一樣時，**短邊會被裁掉**。
重要的東西（字、關鍵物件）不要放在邊緣。

立繪相反，它是完整放進去的，所以立繪可以放心留白。
:::

::: tip 檔案大小
一張圖控制在 **300KB 以內**。實境遊戲是在戶外用手機網路玩的，
而一款遊戲可能有幾十張圖——那是玩家在路邊等著看的東西。

1080×1920 的 JPG 壓到品質 80 大約就是這個量級。

**匯出時會自動幫你壓一次**（見下），所以原圖大一點沒關係——但那是保險，
不是讓你可以完全不管。
:::

## 匯出時會自動壓縮

按「匯出可上架的遊戲」時，底下那個**「壓縮圖片」預設是打勾的**。
匯出完成後畫面上會寫「圖片 42.0 MB → 6.3 MB（壓了 38 張，2 張維持原樣）」。

壓縮的上限**依這張圖會被怎麼看**分兩級：

| 這張圖 | 上限 | 為什麼 |
|---|---|---|
| 背景、立繪、頭像 | 1600px | 滿版顯示但**不能放大**，手機再寬也就 430 點 × 3 倍螢幕 |
| 道具、提示、故事的圖 | 2400px | 玩家**可以放大到 5 倍**湊近看碑文與細節 |

同一張圖被填在好幾個地方時，取**最寬鬆**的那一個。

::: warning 透明度一定會保留
去背的立繪、`type=Overlay` 的數位透明片都有透明背景。壓縮**不會**把它們變成白底或黑底
——程式是掃過圖片實際的透明通道來決定輸出格式的，不是看副檔名猜。

代價是這類圖只能壓成 PNG，壓縮率比照片差。**如果你的去背圖特別大，
先自己在繪圖軟體裡縮到 1600px 會更有效。**
:::

**已經夠小的圖完全不會被碰**（不會重新編碼，所以不會掉畫質）。
動畫 GIF 與 SVG 也會整張跳過。壓完反而變大的話會自動保留原檔。

每一張的處理結果都寫在包裡的 `圖片對照.csv`，多了一欄「壓縮」。

::: tip 什麼時候該取消勾選
只有一種情況：**你的某張圖就是要讓玩家放大到極限看細節**（例如很小的碑文字）。
那時把勾勾拿掉，整包會大很多，但每張圖都是原檔。
:::

## 匯出之後

匯出的資料夾裡有一份 `圖片對照.csv`，記著哪個檔名對應原本哪一條連結、用在哪一格。
圖片有問題時從那裡找最快。
