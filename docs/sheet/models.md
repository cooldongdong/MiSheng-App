# 八種頁面（model）

`rundown` 的 `model` 欄決定這一頁長什麼樣。

| `model` | 是什麼 | 一定要有 |
|---|---|---|
| `Talk` | 對白。最常用的一種 | `text` |
| `Article` | 一整頁可以捲的長文（導覽解說、地方誌） | `text` |
| `Img` | 一張圖 | `url` |
| `Quiz` | 選擇題 | 見下面 |
| `MissionAnswerInput` | 讓玩家打答案 | `missionId` |
| `CustomValueInput` | 讓玩家打一段字（例如取名字） | `customKey` |
| `MissionStart` | 一關的開場（關卡名、背景圖、導航） | `missionId` |
| `GameStart` | 遊戲封面 | `missionId` **要留空** |

## GameStart：封面

通常就是整份 rundown 的**第一列**。

它的內容取自 [config](/sheet/config)（`title`／`description`／`backgroundImg`），
不需要也不可以填 `missionId`——**封面不是一關**。

::: tip 舊的做法還能用
以前的做法是「開一個 id = 0 的假關卡當封面，再從關卡清單藏起來」。
既有的試算表照舊能跑，不用改。
:::

## MissionStart：一關的開場

顯示關卡名、說明、背景圖，還有一顆「開始遊戲」。

`missionId` 一定要指到一個真的關卡——指不到會整頁全黑。

::: tip 提示的倒數從這裡開始算
玩家**離開這一頁往前走**的那一刻才開始計時（見 [hint 的 timer](/sheet/hint)），
不是進到這一頁就開始。停在這裡讀說明、看導航不會被算進去。
:::

## Quiz：選擇題

題目一列，每個選項各一列：

| id | nextId | model | parentId | title | text |
|---|---|---|---|---|---|
| `q1` | | Quiz | | | 你要走左邊還是右邊？ |
| | `left` | | `q1` | 走左邊 | |
| | `right` | | `q1` | 走右邊 | |

- 選項用 **`parentId` 指回題目**
- 選項上的 **`nextId` 決定選了會去哪**
- 選項的文字寫在 **`title`**
- **選項自己不需要 id**

## MissionAnswerInput：作答

玩家打的字要跟那一關的 `answer` 一模一樣才算對。

`missionId` 要指到那一關——而且那一關的 `answer` 不能是空的，
否則玩家不用輸入就能通關。

## CustomValueInput：讓玩家打一段字

用 `customKey` 給它一個名字，之後在任何一頁寫 <code v-pre>{{那個名字}}</code> 就會代入。
見 [rundown 的變數](/sheet/rundown#變數-把玩家打的字叫回來)。

## Article：長文補充

一整頁可以捲的長文，**不會一個字一個字打出來**。

### 什麼時候用它，而不是 Talk

`Talk` 是「有人在對你說話」——底部一個小框、逐字出現。那在一兩句台詞上剛好，
但一段八百字的廟宇沿革放進去，玩家要**等四十秒**才看得完字，而且只能在
一個四行高的小窗裡捲九次。

判準很簡單：**這段文字是台詞，還是資料？**

| | `Talk` | `Article` |
|---|---|---|
| 像什麼 | 有人在跟你說話 | 一份可以讀的資料 |
| 長度 | 一兩句 | 一段到幾段 |
| 逐字打出來 | 是 | 否 |
| 版面 | 底部的對白框 | 整頁，可以捲 |

### 怎麼填

| 欄位 | 用途 |
|---|---|
| `text` | 文章內容（**必填**） |
| `title` | 文章標題，顯示在最上面 |

`missionId` 跟其他頁一樣，留空就是沿用上一關。

::: warning Article 不用 backgroundImg
別的頁面填 `backgroundImg` 是鋪滿整頁的底圖，`Article` **不讀它**——
長文要讀得下去，底圖會把對比讓給美術。

文章裡的圖寫在 `text` 裡（見下面的 `![說明](檔名)`），這樣一篇可以放好幾張，
而且**位置由你決定**。
:::

### 放在哪一列

它就在流程上，所以**想讓玩家什麼時候看到，就放在那個位置**。

最常見的用法是**放在解完謎之後**：玩家答對了、心情正好，這時候給一段這個地方的
來歷。放在關卡開頭的話，他還在想謎題，不會讀。

::: tip 玩家可以直接滑過去
`Article` 不強迫讀完——按 NEXT 或往上滑就走了。它是補充，不是關卡。

右上角有一顆放大鈕，可以把文章攤開成滿版來讀。
:::

## Article 的排版寫法

`Article` 的 `text` 支援六種寫法，**其他 model 不支援**。

| 你在儲存格裡打 | 畫面上 |
|---|---|
| 換行（`Alt` ＋ `Enter`） | 分段。**不需要空行** |
| `## 小標` | 一行小標題 |
| `- 項目` | 清單 |
| `1. 項目` | 數字清單 |
| `> 引言` | 引文（左邊一條線） |
| 三個減號自成一行 | 一條分隔線 |
| `**粗體**` | **粗體** |
| `![說明](檔名)` 自成一行 | 一張圖 |

### 分段就是換行，不用空行

在儲存格裡按 `Alt` ＋ `Enter`（Mac 是 `Option` ＋ `Enter`）換行，畫面上就是新的一段。

這跟一般的 Markdown 不一樣——那邊要空一行才算分段。這裡照試算表的直覺來：
**你看到換行，玩家就看到換行。**

### 數字清單的編號不用自己維護

```
1. 先到廟埕
1. 找到石碑
1. 數一數上面的名字
```

畫面上會變成 1. 2. 3.——**編號是算出來的，不是你填的數字**。
所以中間插一項不必把後面全部重編。

### 放圖：`![說明](檔名)`

自己**佔一整行**就是一張圖：

```
本宮歷經數次遷建，第一代廟宇至今仍保存良好。
![第一代廟宇](miao-1.jpg)
第二代則在民國六十年遷至現址。
![第二代廟宇](miao-2.jpg)
```

- 括號裡填**檔名**（本機資料夾／遊戲資料夾裡的圖）或**完整網址**，
  規則跟 `backgroundImg`、`img` 那些欄位一模一樣
- 方括號裡是圖的說明文字，看不到，但圖載不出來時會顯示
- **玩家可以點開放大**——匾額、碑文、老照片這些要湊近看的東西，這一點很重要
- 想放幾張就放幾張，想放在哪一段之間就放在哪裡

### 沒列在上面的寫法會原樣顯示

`*單顆星*` 不是斜體、`[文字](網址)` 不會變成連結、單顆 `#` 不是標題，
它們會照你打的樣子出現在畫面上。

::: warning 兩顆星是保留字元
因為 `**` 被拿來表示粗體，**落單的 `**` 會原樣顯示在畫面上**。
它不會吃掉後面的內容，但看起來會很奇怪——寫完記得檢查有沒有漏掉配對的那一半。
:::
