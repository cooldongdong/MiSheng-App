# 試算表怎麼填

一份遊戲是七張表。你不需要一次搞懂它們——**先把 rundown 填出來，遊戲就會動**，
其他六張都是在替 rundown 補東西。

> 最快的方式其實是**先去玩一次 [demo](https://misheng.app/demo)**。
> 那款遊戲本身就在解釋這七張表，玩完再回來看這一頁會快很多。

---

## 一句話認識這七張表

| 表 | 它管什麼 | 沒填會怎樣 |
|---|---|---|
| **rundown** | 遊戲從頭到尾的每一頁 | 沒有遊戲 |
| **mission** | 有哪些關卡、答案是什麼 | 沒有關卡可解 |
| **character** | 誰在說話、長什麼樣 | 對白沒有頭像與立繪 |
| **config** | 這款遊戲叫什麼、封面 | 無法生成 |
| **hint** | 每一關的提示 | 玩家卡住只能問你 |
| **prop** | 道具（圖片、轉盤、相機） | 沒有道具頁 |
| **story** | 劇情圖 | 沒有故事頁 |

**rundown 是主角**，其他表都是被它指到才會出現。

---

## 表與表之間怎麼連起來

這是整份資料唯一需要記住的規則：

> **一列需不需要名字，看有沒有別的欄位指向它；名字放在哪一欄，看那個指標指的是什麼。**

```
rundown.nextId    ─┐
rundown.parentId  ─┴→ rundown.id       （流程要跳到哪一列）

rundown.missionId ─┐
hint.missionId    ─┤
prop.missionId    ─┼→ mission.id       （這一列屬於哪一關）
story.missionId   ─┘

rundown.speaker   ─┐
hint.speaker      ─┴→ character.name   （誰在說話）
```

從這張圖可以直接推出「哪一欄非填不可」：

- **mission.id 必填**——四張表都靠它找到關卡
- **character 靠 name 不靠 id**——所以 `name` 不能空、不能重複；`character.id` 是廢的
- **rundown.id 只有「被 nextId／parentId 指到」的那幾列才要填**，其餘留空就好
- **hint／prop／story 的 id 完全不用填**——沒有任何人指向它們

> 這些 id 可以是**任何文字**，不一定是數字。`第三章`、`土地公廟`、`ending-A` 都可以，
> 而且比 `47` 好記得多。唯一的要求是「同一張表裡不重複」。

## rundown：遊戲的每一頁

一列就是玩家會看到的一頁。玩家往下滑，就是往下一列走。

### 最重要的三欄

| 欄位 | 說明 |
|---|---|
| `model` | 這一頁長什麼樣（見下面「七種頁面」） |
| `text` | 這一頁的文字 |
| `speaker` | 誰說的（要對得上 character 表的 `name`） |

**流程預設是「照著列的順序往下走」**，所以多數時候 `id`、`nextId` 都可以留空。
只有要跳到別的地方時才填。

### 七種頁面（`model`）

| `model` | 是什麼 | 一定要有 |
|---|---|---|
| `Talk` | 對白。最常用的一種 | `text` |
| `Img` | 一張圖 | `url` |
| `Quiz` | 選擇題 | 見下面 |
| `MissionAnswerInput` | 讓玩家打答案 | `missionId` |
| `CustomValueInput` | 讓玩家打一段字（例如取名字），之後可以叫出來 | `customKey` |
| `MissionStart` | 一關的開場（關卡名、背景圖、導航） | `missionId` |
| `GameStart` | 遊戲封面。資料取自 config | `missionId` **要留空** |

`GameStart` 通常就是整份 rundown 的**第一列**。

### Quiz 怎麼填

題目一列，每個選項各一列：

| id | nextId | model | parentId | title | text |
|---|---|---|---|---|---|
| q1 | | Quiz | | | 你要走左邊還是右邊？ |
| | a-left | | q1 | 走左邊 | |
| | a-right | | q1 | 走右邊 | |

- 選項用 **`parentId` 指回題目**
- 選項上的 **`nextId` 決定選了會去哪**
- 選項的文字寫在 **`title`**
- **選項自己不需要 id**

### 其他欄位

| 欄位 | 說明 |
|---|---|
| `title` | 這一頁的標題；Quiz 選項則是選項文字 |
| `backgroundImg` | 這一頁的背景圖 |
| `url` | `Img` 的圖片網址；Quiz 選項填了它就變成外部連結 |
| `textAnimation` | 對白要不要一個字一個字出現 |
| `customKey` | `CustomValueInput` 用它當名字，之後在文字裡寫 `{{那個名字}}` 就會代入玩家打的字 |

## mission：關卡與答案

| 欄位 | 說明 |
|---|---|
| `id` | **必填、不可重複**。四張表都靠它指到這一關 |
| `title` | 關卡名 |
| `subtitle` | 副標（三個字以內才會顯示） |
| `description` | 關卡說明，顯示在開場頁 |
| `answer` | 正確答案。**多個答案就在同一格裡換行**（`Ctrl`＋`Enter` / `Cmd`＋`Enter`） |
| `similarAnswer` | 「很接近了」的答案，玩家打到會得到不同的回應 |
| `successText` | 答對時說什麼 |
| `giveUpText` / `confirmGiveUpText` | 放棄時說什麼 / 放棄前的確認 |
| `backgroundImg` | 這一關的背景圖 |
| `navigation` | 一條地圖連結。填了開場頁會出現「導航」按鈕 |

---

## character：角色

| 欄位 | 說明 |
|---|---|
| `name` | **必填、不可重複**。rundown 與 hint 的 `speaker` 靠它找到這個角色 |
| `avatar` | 頭像圖 |
| `straight` | 立繪圖 |

> **不想登記角色也可以**：`speaker` 留空、改用 `title` 寫名字，畫面上照樣顯示，
> 只是不會有頭像與立繪。

---

## config：這款遊戲的設定

只有一列。

| 欄位 | 說明 |
|---|---|
| `id` | **這款遊戲的名字，也是玩家存檔的名字。空的話玩家的進度不會被記住** |
| `title` | 遊戲標題（也是封面上的字） |
| `description` | 一句話介紹（也會顯示在封面） |
| `backgroundImg` | 封面圖 |
| `duration` | 大約要玩多久 |
| `developer` / `creator` / `designer` | 誰做的 |
| `recordUrl` | 選填。玩家的紀錄要送到哪裡（見[收集玩家的遊戲紀錄](/docs/collect)） |

其餘欄位（`version`、`type`、`releaseDate`、`languagesSupported`、`contactInformation`）
目前只是登記用，不影響遊戲。

---

## hint：提示

| 欄位 | 說明 |
|---|---|
| `missionId` | 這是哪一關的提示 |
| `text` | 提示內容 |
| `speaker` | 誰說的（選填） |
| `img` | 附圖（選填） |
| `timer` | 選填。**進這一關之後第幾分鐘自動解鎖**。填 `0` 代表進關就解鎖，留空代表只能手動 |

同一關的提示會照表裡的順序顯示。**玩家隨時可以手動解鎖**——`timer` 是安全網，不是限制。

---

## prop：道具

| 欄位 | 說明 |
|---|---|
| `missionId` | 這是哪一關的道具 |
| `type` | `Img`（一張圖）／`Wheel`（轉盤）／`Camera`（相機透明片） |
| `title` | 道具名稱 |
| `img` | `Img` 的圖；`Camera` 疊在相機畫面上的透明圖 |

**轉盤（`Wheel`）**由四層圖疊起來，由下往上：

| 欄位 | 那一層 |
|---|---|
| `backImg` | 最底，不會轉 |
| `rotateImg2` | 會轉 |
| `rotateImg1` | 會轉 |
| `frontImg` | 最上，不會轉 |

四層都是選填，但**沒有 `rotateImg1` 就沒有東西可以轉**。

---

## story：劇情圖

| 欄位 | 說明 |
|---|---|
| `missionId` | 這是哪一關的故事 |
| `title` | 標題（選填） |
| `img` | 圖片 |

---

## 圖片怎麼填

所有 `img` / `avatar` / `backgroundImg` 之類的欄位，填**圖片的網址**。

Google 雲端硬碟的分享連結可以直接貼——謎生會自己轉換。記得把權限設成
「知道連結的人都可以檢視」，否則玩家看不到。

也可以把圖片放在自己的資料夾，在 `/create` 選「改用本機資料夾」，那時候這些欄位
改填**檔名**就好。

## 常見狀況

### 我加了一欄，結果整份都變紅

新增欄位不會讓遊戲壞掉，但**謎生不認得的欄名會跳提醒**，因為那一格的資料永遠不會
被讀到——而最常見的原因是打錯字（`backImgg`、`rotateimg1`）。

自己加註記欄（「誰負責」「備註」）是可以的，那個提醒可以忽略。

### 我改了試算表，遊戲沒變

在 `/create` 按「重新讀取」。已經匯出、部署的遊戲則是改 `game/` 資料夾裡的 CSV
再重新上傳。

### 玩家的進度不見了

先確認 `config` 的 `id` 有填——**它是存檔的名字，空的話所有進度都不會被記住**，
而畫面上完全看不出來。

### 關卡頁是空的

`mission.id` 沒填，或 rundown 的 `missionId` 指到一個不存在的關卡。
`/create` 的檢查報告會直接告訴你是哪一列。
